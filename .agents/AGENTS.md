

- **Matrix API Reference**: Before adding a new method to `matrix` or `matrix.h`, check `.agents/MatrixAPI.md` — a full map of every constructor/factory/method already on `matrix`, grouped by category (shape ops, reductions, arithmetic, linear algebra, autodiff/JIT, refcounting, etc). Avoids duplicating existing functionality.
- **Creating New Operations**: When asked to add a new primitive or operation to the compute graph, you MUST read `.agents/AddingNewOps.md` to understand the 5-step pipeline for frontend building, dimension collapsing, and CPU/Metal multidimensional dispatching.
- **Testing Standard**: All new mathematical ops must be verified against an exact Python equivalent using `mlx.core` (saved as a temporary `test_mlx_{op}.py`), and tested inside the `computational_graphV2` function in `MatrixH.mm`. You MUST delete the python test script after verification to avoid polluting the workspace.
- **Rendering Architecture**: For the `GeoNode`/`Viewer`/`Controllers` scene-graph and render-loop pattern (the current, modern approach — model new rendering code on this), see `.agents/Rendering_3D.md`. For the two superseded systems it replaced (`Shape<T>` and `GeometryNode<T>`, still physically present in `MatrixH.mm`/`Mods/GeometryNode.mm` and still drawn by the legacy `Renderer` path), see `.agents/Legacy_Rendering.md` — do not model new code on those.
